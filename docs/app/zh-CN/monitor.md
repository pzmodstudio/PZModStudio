# 监控中心

监控中心实时显示游戏写入的日志，并把每个错误变成一张卡片，写明游戏把它归咎于哪个模组，以及你可以怎么处理。无论你是从 Studio 还是从 Steam 启动游戏，它都会跟踪 `console.txt`。

## 你会看到什么

- 左侧是日志查看器，每个日志一个标签页。
- 右侧是**错误和警告**：错误卡片，上方是**找出导致问题的模组**面板。
- 顶部的**查看游戏运行情况**会打开“诊断 > 游戏 > 实时”：内存、CPU，以及游戏当前在哪个画面。
- 游戏运行时（完整视图），日志上方是**实时**面板：见下文。
- 顶部的 **📁 日志文件夹**会在 Windows 资源管理器中打开包含 `console.txt` 和 `Logs` 子文件夹的文件夹。
- 旁边是垃圾信息过滤按钮。显示**垃圾过滤：已开启**时，它会隐藏关于缺少翻译的行；点击它可切换为**过滤：显示全部**。

如果还没有设置游戏文件夹，界面只会显示**在设置中配置目录路径**。

## 实时（游戏运行时）

在完整视图中，游戏打开时日志上方会有一个**实时**面板。它的标题行是汇总（FPS、Java 内存、CPU、Lua 错误）；点击可折叠。它每 2 秒读取一次：

- **FPS，最近几分钟**：最近 10 分钟的曲线（把鼠标移到上面可以查看某一时刻）；虚线是 30 FPS。下面是平均帧时间和最近 10 秒最长的一帧、Java 已用内存与其上限、整个进程的内存及电脑的剩余内存，以及 CPU。第二条曲线跟踪内存。
- **当前 Lua 耗时，按模组**：最近 10 秒内 Lua 耗时最多的 5 个模组，单位是每秒游戏时间的毫秒数。数据来自 Studio 的性能分析器。性能分析器关闭时不计时，面板会这样提示，并提供**下次启动时开启**：性能分析器会排在模组列表的最前面（以及你最后游玩的存档中），从下次启动游戏开始测量。
- **本次游戏的 Lua 错误**：有多少个，以及游戏归咎于哪些模组，按 Studio Link 在游戏中的统计；下面是最新的错误卡片，在你观看期间出现的会标为**新**。
- 最后一行说明 Link 的浮层是否在游戏中显示，以及它自身代码的开销。

FPS、Java 内存和错误来自 Studio Link（1.20 或更新版本），在你进入游戏后才有。游戏关闭后面板会消失。

### 游戏中的浮层

Studio Link 可以在游戏画面上显示同样的数字：FPS 和帧时间、Java 内存与其上限、CPU、最近 10 秒 Lua 耗时最多的 5 个模组（需开启性能分析器），以及本次游戏的 Lua 错误和被归咎的模组。在暂停菜单中用**实时浮层**打开它，或在游戏的**游戏选项 > 模组 > PZ Mod Studio Link** 中给它设一个快捷键（在你选择之前它没有快捷键，所以不会占用游戏的按键）。把它拖到你想要的位置；它会留在那里，下次游戏也会回到那里。它的最后一行说明它自身的开销，单位是每秒毫秒数。内存上限和 CPU 只有在 PZ Mod Studio 打开时才知道。

## 日志查看器

总有两个标签页：

- **console.txt（客户端）**：实时的游戏日志。Studio 从文件末尾开始读取，所以你看到的是 Studio 打开之后发生的事。新的游戏会话开始时，文件会重新开始，Studio 从它的第一行读起。这个标签页保留最新的 1,500 行，即使你在其他界面也是如此。
- **专用服务器（实时）**：专用服务器的日志，在你从**服务器**界面启动的服务器运行时显示。它显示最新的 1,500 行，每 2 秒重新读取一次。

要阅读其他日志，点击**载入日志**。菜单会列出在你的 Zomboid 文件夹中找到的日志（附带大小）；选一个在新标签页中打开。**📂 浏览其他文件（.txt）...** 可以打开任何文本文件。载入的日志显示最后 2,000 行。这些标签页可以用 X 关闭；两个实时标签页不能关闭。

标签页下方：

- 搜索框只保留包含你输入内容的行。
- **全部**、**🚨 错误**、**🌙 Lua** 和 **☕ Java** 小标签只保留该类型的行。**⚡ Bridge** 只在开启开发者功能时出现。
- 底部显示当前显示的行数和总行数。

标签页右侧的小按钮：

- 磁盘按钮把标签页中的内容保存为 `Zomboid/Logs/` 中的一个新文件。
- 复制按钮把你能看到的行（经过筛选后）复制到剪贴板。
- 垃圾桶按钮清空这个标签页的查看器。它不会动磁盘上的文件。

错误行显示为红色，警告显示为琥珀色。

## 错误卡片

当游戏抛出错误，或写入一条警告并提到某个模组时，会出现一张卡片。其他一切都留在左侧的日志中。抛出的错误（红色）排在前面，警告（琥珀色，标为**警告 · 游戏继续运行了**）排在后面。同一个问题只出现一次，不管游戏重复了多少次；像 **600×** 这样的数字表示它在日志中出现了多少次，重复出现的那些最值得先修。

卡片上方，一个徽标统计异常数，另一个统计警告数（每张卡片都会说明是否需要处理），还有一行概括整个日志。当 Studio 记得之前的游戏记录时，每张卡片会显示**新**或**自某日期以来在 N 次游戏中出现过**，**只看新的**会隐藏其余的。

卡片可能显示：

- **模组的名称**，当游戏在错误行或其下方的堆栈跟踪中提到它时。
- **由 ... 调用**：调用了出错代码的模组，从游戏自己的堆栈中读取。问题可能出在其中任何一个。
- **日志片段**：那一行本身。
- 对于失败的 `require`，如果 Studio 找到了，会显示那个模块现在实际在哪里。
- 接下来该怎么做，或者说明 Build 42 兼容层已经处理了它。
- 当错误出在你的 Studio 补丁包所保存的副本中时：如果模组在制作副本之后修改了那个文件，或者你列表中已经没有任何模组带有那个文件，会有一条说明。

新的游戏会话开始时，上一次的卡片会被清除。**丢弃**可以手动清除它们。

## 从卡片修复

- **修复路径**（或**修复 File.lua 中的路径**）：当某个模组用旧路径请求模块、而 Studio 知道新路径时出现。它会改写当前模组中所有请求该模块的文件里的 `require`，并把它们发布到你的 Studio 补丁包中。模组本身不会被修改，仍保持启用。一行绿色文字会说明修复了什么；请重新启动游戏。
- **修补 File.lua** 或**修补它的某个文件**：在模组合并器中打开该模组的文件，让你修正其中一个。你的副本会放进一个最后加载的补丁包，所以游戏读取的是它而不是模组的。没有已知修复办法的警告不会有这个按钮。
- **移除 File.lua 的副本**：当错误出在你的 Studio 补丁包已经修补过的文件中时出现。它会（先询问）把那份副本从补丁包中拿掉，游戏会重新读取模组自己的文件。你对副本做的任何编辑都会丢失。
- **禁用它**：请你确认后禁用该模组，并带你到模组列表。
- **合并补丁包也许能修复这个问题——打开模组合并器**：用于 Build 42 兼容层能处理的错误。兼容层包含在已发布的合并补丁包中；卡片会告诉你你的补丁包是已经生效还是仍是草稿。

## 报告

- **保存报告**会写一个 Markdown 文件，包含错误、你的游戏版本、该模组及其代码，以及前后的日志行。可以直接交给模组作者或 AI 助手。
- **复制报告**把同样的报告放到剪贴板。
- **🔍 在日志中查看**把错误中的文件名或关键词放进左侧的搜索框。
- **复制这一行**只复制错误那一行。

## 找出导致问题的模组

用于日志里没有写明的问题：卡死、某个配方始终不出现、某个存档打不开。

1. 打开面板。如果问题不是每次都出现，勾选**不是每次都出现**。如果日志中有错误的某段文字，输入它：每次测试游戏后，本应用会读取日志并给出建议的答案。点击**开始对半排查列表**，然后确认。
2. 嫌疑模组中的一部分会被启用；这台电脑已经怀疑的那些（出过问题的游戏记录、重复出现的错误）会被优先尝试。被其他模组需要的模组在每一轮中都保持启用，所以不会因为这个原因出问题。
3. 点击**启动游戏**，按问题发生时的方式玩一下，然后关闭游戏。
4. 回答**还会发生**或**没有了**。列表会再次对半分。徽标显示当前轮次和还剩几次启动（一百个模组大约 8 次）。
5. 只剩一个模组时，再玩一次确认。

最后，面板会写明是哪个模组，显示日志中关于它的行（某行提到文件时有**修补 File.lua**，还有**在控制台中显示它的行**），并提供**修补它的某个文件**、**禁用它**或**保持启用**。不论排查如何结束，你原来的列表都会被放回去。**停止并恢复我的列表**会提前结束排查。

如果最后那个模组单独并不会导致问题，排查会自动继续：它会保持该模组启用，寻找与它一起导致问题的另一个模组，然后写明这一对。如果既没找到单个模组也没找到一对，面板会说明原因：是某个前置模组、超过两个模组，或者根本不是模组的问题。

## 小提示

- 排查过程会自己写入你的模组列表。排查进行时不要在模组列表中启用或禁用模组，否则下一个答案就没有意义了。
- 关闭 Studio 后排查仍会保留；它保存在 `Zomboid/PZModStudio_Bisect.json` 中。
- 排查中的**启动游戏**会以普通方式启动游戏，不带调试模式。
- 发布到补丁包中的修复在下次启动游戏时生效。

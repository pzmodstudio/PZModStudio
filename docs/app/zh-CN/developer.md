# 开发者

“开发者”界面是给制作模组的人用的。你可以创建新模组、在游戏之前检查模组的每个文件、只启用该模组来启动游戏、在游戏运行时重新加载它的 Lua、检查它在多人游戏中以及在已安装游戏版本上的表现、编写翻译草稿、把它发布到 Steam 创意工坊，以及启动地图编辑器。

## 你会看到什么

只有在**应用设置**中打开**开发者功能**后，这个界面才会出现在侧边栏中，而且和其他界面一样，需要有一个当前配置方案。顶部的**你正在制作的模组**保存所有工具要处理的模组，并有**打开它的文件夹**和**只启用此模组启动游戏**。下面每个工具一个标签页：**检查文件**、**实时重载**、**多人游戏**、**对照游戏版本**、**翻译**、**创意工坊**、**地图**和**新模组**。标签页有话要说时（发现问题、正在监视、多人游戏的结论）会显示一个小徽标。Studio 会记住你上次打开的标签页。除了**创意工坊**、**地图**和**新模组**，每个标签页都需要先选择一个模组。

## 制作新模组

1. 打开**新模组**标签页。
2. 填写**名称**、**ID**（文件夹名和列表条目：字母、数字、`_` 和 `-`；在你修改它之前，它会跟随名称变化）、**作者**和**描述**。
3. 如果模组也要在 Build 41 上运行，勾选**也支持 Build 41**。
4. 点击**创建**。

Studio 会按 Build 42 读取的方式在 `Zomboid/mods` 中创建模组：`42/mod.info`、`42/media/lua/client`、`server` 和 `shared` 文件夹、`42/media/scripts`、`common/media/lua`、一张待替换的封面图，以及一个在游戏加载时打印模组名称的 Lua 文件。它会拒绝不是普通名称的 ID 或已经存在的文件夹。**打开文件夹**会在 Windows 资源管理器中打开它，新模组会被选为你正在制作的模组。准备好后，在模组列表中启用它。

## 选择你要制作的模组

在**你正在制作的模组**下，从列表中选择一个模组。模组按来源分组，你正在制作的排在前面：**你上传的创意工坊项目（Zomboid/Workshop）**、**Zomboid/mods 中的文件夹**、**从 Nexus、文件或链接安装的**、Studio 为你的游戏版本改编的副本、**Studio 自己的模组**，最后是**创意工坊订阅**，供参考。列表下方显示模组的 ID、版本、创意工坊编号和文件夹。**打开它的文件夹**会打开模组的文件夹。Studio 会记住你的选择。

## 检查每个文件

在**检查文件**标签页中，点击**检查每个文件**。每个 `.lua` 文件都会经过模组合并器使用的同一个 Lua 解析器，每个 `media/scripts/*.txt` 都会经过括号检查（游戏遇到第一个不配对的块时，会悄悄丢掉整个脚本文件）。结果会显示在按钮正下方，并注明检查了多少个 Lua 和脚本文件。它会显示**每个文件都能读取**，或按文件列出问题及其行号和列号。点击一个问题，会在 VS Code（如果已安装）中打开该文件的那一行，否则用 Windows 为该文件指定的程序打开。

这里只检查语法。游戏如何处理这些文件，请在监控中心查看。

## 只启用此模组启动游戏

界面顶部的**只启用此模组启动游戏**会以调试（窗口）模式启动游戏，只启用这个模组、它需要的模组以及 Studio 的 bridge。你的模组列表会被暂时放到一边，一个横幅会说明这一点。游戏关闭时列表会恢复，也可以用**立即恢复我的列表**马上恢复。该列表也会保存在模组列表的**以前的列表**中。这样的启动运行期间，按钮不可用。

## 在游戏运行时重新加载

这让你修改一个 Lua 文件后无需重启就能在游戏中看到效果。

1. 启用 bridge 模组（`Z_PZModStudio_Bridge`）启动游戏。
2. 打开**实时重载**标签页，打开右侧的开关。它会显示**正在监视（模组名称）**。
3. 保存模组的一个 Lua 文件。Studio 在保存的那一刻就会发现它，用解析器检查后发送给游戏，游戏会在主菜单、游戏中或暂停时重新加载它。

**立即重新加载此模组的所有 Lua** 会一次发送该模组的所有 Lua 文件。

按钮下方的日志显示每一步：

- **已更改：**一个文件已发送给游戏。
- **未发送，无法解析：**该文件有语法错误，附带行号、列号和消息。它不会被发送，所以游戏永远不会运行有问题的代码。
- 游戏对每个文件的回应，成功时为绿色，失败时为红色。
- 各个时间点：发现、发送、在游戏中生效、回到 Studio，单位是毫秒。
- 没有可以重新加载的对象时显示**游戏没有在运行**或 **6 秒内游戏没有回应**（检查 bridge 模组是否已启用）。

文件被重新加载时，它的顶层代码会再次运行，而 bridge 会保留那样做会破坏的东西：

- **事件处理函数**：文件添加的每个处理函数只运行一次，你新添加的处理函数开始工作，你从文件中拿掉的处理函数停止工作。
- **表**：当文件再次创建一个全局表时（`MyMod = {}`、`MyPanel = ISPanel:derive(...)`），旧表会被保留并获得新的函数，所以打开的窗口和保存的引用会带着它们的状态运行新代码。旧表已有的值会保留旧值（bridge 分不清你的状态和你修改过的常量）：要让修改的常量生效，请完整重置 Lua（Reset Lua）。
- **你自己的初始化**：`if PZStudio then PZStudio.onReload(function(file) ... end) end` 会在该文件每次重新加载后运行，用于 `OnGameStart` 做过、但不会再做一次的事情。
- **`require` 它的文件**：模组中用 `require` 加载被修改文件的其他文件，会紧接着它重新加载，从而获得它的新代码。

日志会说明保留了什么，例如“保留了 1 个处理函数、1 个表”。

## 多人游戏检查

在**多人游戏**标签页中，**检查此模组的多人游戏兼容性**会查看模组的 client 和 shared Lua 中直接修改世界、车辆、动物或地图的调用，而游戏自己的代码在这些地方会改为请求服务器。每个发现都会显示文件、行号，以及在服务器上执行该操作的游戏处理函数。位于 `if isClient()` 分支内的调用算作已处理。点击一个发现可在你的编辑器中打开它。它只检查这些调用：没有列出任何问题的模组，在多人游戏中仍可能以这里看不到的方式出问题。

## 对照已安装的游戏版本

在**对照游戏版本**标签页中，**检查此版本有哪些名称**会在你已安装的游戏中查找模组的 Lua 调用的每个名称：游戏的 Java 类和方法、全局函数、游戏自己的 Lua 和它触发的事件，以及此模组和你的其他已启用模组所定义的内容。剩下的就是会在那一行失败的调用：Build 42 删除的函数、改了名的方法、不再触发的事件、拼写错误。发现按全局函数、方法和事件分组，每个都附带文件和行号，当有相近的已知名称时还会给出“你是不是想用”。点击一个可在你的编辑器中打开它。文件中只提到而不调用的名称（`if foo then`）算作有防护，会被略去。

第一次检查会读取游戏文件，需要几秒钟；之后按游戏版本缓存。它只按名称判断：游戏运行时才构造出来的名称看不到，带有 Java 的模组可能定义了 Lua 看不到的名称（结果会注明）。请打开那一行自行判断。

## 翻译草稿

**翻译**标签页显示模组所用的语言、它有多少条文本，以及它的各种语言，分组为：缺少文本的、完整的，以及模组中不属于游戏语言的文件夹。勾选你想要的语言并点击**编写草稿…**：Studio 会为每种语言缺少的每条文本写一份草稿，翻译服务与翻译模组简介所用的相同（**应用设置**中的**翻译**），写入模组自己的 `Translate/<LANG>/` 文件夹。已有的内容保持不变。**打开 Translate 文件夹**会打开它。草稿只是起点，不是正式翻译：发布前请通读一遍。

## 发布到创意工坊

**创意工坊**标签页通过这台电脑上运行的 Steam 客户端把模组上传到 Steam 创意工坊。它使用与游戏自带上传工具相同的文件，位于 `Zomboid/Workshop/<item>/`：`workshop.txt`、`preview.png` 和 `Contents/mods/<mod>/`。

1. 在列表中选择一个项目。对于 `Zomboid/mods` 中你自己的、还没有项目的模组，点击**为创意工坊准备（模组）**：它会创建项目文件夹，放入模组的副本、根据它的 `mod.info` 生成的 `workshop.txt`，并把它的封面图作为预览图。
2. 填写**标题**、**可见性**（**公开**、**仅好友**、**私密**或**不公开（通过链接）**）、**标签（用 ; 分隔）**和**描述**（Steam 最多接受 8000 个字符），然后点击**保存 workshop.txt**。
3. **查看文件**显示将要发送的内容，以及自上次从 Studio 上传以来有什么变化。项目文件夹中的 `.workshopignore`（每行一个模式，例如 `*.psd` 或 `.git/`）可以排除文件。
4. 如果需要，写一段更新说明，然后点击**发布到创意工坊**（对已发布的项目则是**上传更新**）。会先询问你。Steam 必须在运行，并登录拥有该项目的账号。

发送的内容以 `workshop.txt` 为准：在 Steam 页面上做的修改会被下一次上传替换，游戏也是这样做的。如果 Steam 在你接受创意工坊法律协议之前把新项目隐藏，结果会说明这一点并附带链接。**查看创意工坊页面**会在你的浏览器中打开该项目。Studio 不会上传别人的模组：当项目中包含你订阅的模组时，它会说明这一点，按钮保持不可用。列表旁边的垃圾桶按钮会把项目文件夹从 `Zomboid/Workshop` 中拿掉（移到回收站）；Steam 上不会有任何变化。

## 地图工具

在**地图**标签页中，TileZed 用来绘制每个地图格的图块（建筑、房间、家具、地面）；WorldEd 用来在世界网格上摆放地图格，并写出游戏读取的地图文件。它们由 The Indie Stone 以一个 zip 提供，你可以解压到任何地方。Studio 会在常见位置（你的用户文件夹、文档、桌面、下载、C: 盘）以及你在每个工具下方的框中输入的文件夹里查找它们。找到后，**启动 TileZed** 或**启动 WorldEd** 会从它自己的文件夹启动它。地图模组的地图格放在模组的 `media/maps/<name>` 中。

## 小提示

- 重新加载需要游戏在运行并启用 bridge 模组；其他工具不需要游戏。
- 在游戏中重新加载无需重启；你在表中修改的常量会保留旧值，直到完整重置 Lua。
- 除了**创意工坊**、**地图**和**新模组**，每个工具都需要选择一个 Studio 知道其文件夹的模组。

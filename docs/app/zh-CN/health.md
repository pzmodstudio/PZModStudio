# 诊断

“诊断”汇集了本应用对你的模组、游戏和服务器所了解的一切。顶部有四个按钮：**概览**、**模组**、**游戏**和**服务器**。它总是从概览打开；每个部分都会记住你上次查看的标签页。

## 概览与医生

- 三张卡片，每个部分一张，各用一行说明状况。**模组**：有会弄坏游戏的问题、有值得修复的问题，或者一切正常。**游戏**：开着还是关着、用了多少内存、上次启动、内存上限，以及是否有某次游戏内存不足。**服务器**：这台电脑上是否有服务器在运行，以及它的状况。点击卡片打开对应的部分。
- 下面是**医生**：它会问你哪里不对（**游戏崩溃或无法启动**、**某个模组不起作用**、**游戏很卡**、**其他问题**），然后结合本应用已经知道的信息一步步带你排查：模组检查发现的问题、监控中心的错误，以及游戏内存不足的那些时候。当某一步把你带到别处时，回来后仍然是同一步。**重新开始**回到最初的问题。
- 最顶部的**医生**按钮可以从任何界面打开这一页。

## 模组

按游戏读取的方式检查你已启用的模组，并列出发现的每个问题，附带修复按钮。它会检查你的游戏版本能加载什么、缺少或已禁用的前置模组、加载顺序、不兼容的模组、两个模组都修改的文件，以及上次游玩时刷满控制台的模组。

- 顶部：你的**游戏版本**以及已启用的模组数量。
- **Studio 备注**（例如 **Studio 备注：22 个模组**）：本应用内置的加载顺序规则、不兼容组合和已知问题。当你用**不再发生**标记过一些警告时，旁边会有一个按钮显示数量，并能重新全部显示它们。
- **重新检查**会再运行一次检查。你的列表变化时它也会自动运行。
- 五个标签页；前三个会显示有多少行需要处理：
  - **现在要做的**：会弄坏或将会弄坏游戏的问题（缺少或已禁用的前置模组、加载顺序、你的游戏版本无法加载的模组、不兼容的组合）。**自动修复 N 个问题**在这里。下方折叠着：Studio 已经修复的内容和仅供了解的内容。
  - **冲突**：两个模组提供了同一个文件、物品、配方或文本；游戏只会用其中一个，用哪个由你决定。**自动合并 N 个文件**在这里。
  - **安全**：模组可能做的超出模组范围的事（见下文）。
  - **审查**：逐个列出你的模组，每个都归入一个结论：**已损坏**、**需选择**、**不需要**、**需检查**或**保留**。点击一个模组查看原因，点击**前往**跳到对应的警告。
  - **每个模组的耗时**：游玩时哪些模组拖慢了游戏（见下文）。
- 每行显示模组、问题所在、一个简短的代码（如 `missing_dependency`），右侧是修复按钮。**复制给助手**会把这一行连同一个问题一起复制，方便粘贴到任何聊天助手中；Studio 不会发送任何内容。模组列表中的问题小标签会打开包含该问题的标签页。

如果没有任何问题，你会看到**你已启用的 N 个模组中没有发现问题。**

### 每一行该怎么处理

每一行都会说明以下四种情况之一，和模组列表中的一样：

- **你需要处理**：在你采取行动之前，游戏会出问题或不加载这个模组。从这里开始。
- **值得处理**：能用，但值得修复（顺序不对、有更新还没下载、某个模组刷满控制台）。按钮会说明它会改变什么。
- **仅供了解**：什么都不用做，只是让你知道（两个模组定义了同一样东西、自你上次游玩以来更新过的模组）。
- **Studio 已经修复**：不用管，它就是这样工作的（兼容副本、你补丁包中的文件）。如有需要，每一项都可以撤销。

点击每个分区的标题可以折叠它。

### 它能发现的问题

- `missing_mod`（未安装）：你列表中的某个模组不在磁盘上。如果有一个已安装的模组 ID 几乎相同，它会提议改为启用那个模组。
- `not_for_build`、`outside_version_range`、`invalid_mod_info`：游戏不会在你的版本上加载这个模组，或者它的 `mod.info` 有问题。
- `missing_dependency`：该模组需要另一个没有安装的模组。
- `dependency_not_enabled`：需要的模组已安装但已禁用。
- `dependency_after`、`load_after_order`、`load_before_order`：两个模组的顺序不对。
- `dependency_unavailable`：某个需要的模组自己无法加载。
- `incompatible`：该模组说明它与你已启用的另一个模组不兼容。
- `duplicate_entry`：同一个模组在列表中出现了两次。
- `two_mod_managers`：除了 Studio Link 之外，还启用了另一个会绘制游戏模组界面的模组管理器。
- `workshop_update_pending`：Steam 上有一个更新的版本还没下载。服务器会拒绝模组版本不同的玩家。
- `file_conflict`：两个模组带有同一个文件，游戏只使用最后一个。
- `function_overridden`（**切断了另一个模组**）：某个模组在另一个模组修改了游戏（或另一个模组）的某个函数之后又替换了它，于是那次修改永远不会运行。当一个模组的许多函数被另一个模组切断时（同一个模组的两个版本同时启用），会合并成一行。启用 Studio Link 时会在运行中的游戏里核实：该行会显示**在运行中的游戏里看到**，或者当游戏中用的是另一个模组的版本时显示 `function_seen_other`（**游戏中是另一个版本**）。
- `java_link_broken`（**Java 比此版本旧**）：该模组的 Java 用到了已安装游戏中已经没有的类、方法或字段（某次更新改了它们）。这段代码运行时会失败。如果监控中心显示它失败了，请找找该模组的更新或禁用它；如果它能正常工作，说明该模组会先做检查。
- `tiledef_clash`：两个模组用同一个 `tiledef` 编号、不同的图块表来登记图块，所以有些图块会显示成另一个模组的，或者消失。只保留一个启用，或请作者改一下编号。`file_conflict` 行也会说明上次游戏的日志（使用同样的列表）是否证实了游戏用的是哪一份。
- `game_folder_changed`（**游戏文件夹有变化**）：游戏运行期间，它自己文件夹中的文件发生了变化，而游戏从不往那里写入。本应用会在游戏打开和关闭时比较游戏文件夹、Zomboid 文件夹（不含存档和日志）以及 ZombieBuddy 的文件夹，仅在本应用打开时进行。
- `script_definition_conflict` 和 `translation_conflict`：两个模组以不同方式定义了同一个物品、配方或名称；最后加载的那个胜出。以 `_stale` 结尾的行表示你以前合并过，但之后某个模组有了变化；`_settled` 表示你的补丁包已经解决了它。
- `floods_console`（在模组列表中显示为**刷满控制台**）：在你上次游戏中，这个模组往控制台写了超过 1,000 行错误。这会拖慢游戏，还会掩盖其他模组的错误。请在监控中心中查看它们，或禁用该模组。
- `user_rule_order`：你自己的某条加载顺序规则被违反了。
- `community_rule_order`、`community_incompatible`、`community_known_issue`、`community_successor`：Studio 的规则和模组索引对你的模组的说明。已知问题带有**不再发生**：在这台电脑上不会再显示。
- `learned_issue`：某个模组在你使用同一版本的 3 次或更多游戏中出现的错误（见“这台电脑学到了什么”）。
- `package_built_for_other_list`：你的 Studio 补丁包是用与此配置方案不同的模组列表制作的。
- `package_file_stale`：你的补丁包带有某个模组文件的旧副本，而该模组之后修改了那个文件。游戏读取的是旧副本。
- `package_file_differs`、`package_file_orphan`：你的补丁包带有一个列表中只有一个模组提供的文件，或列表中没有任何模组提供的文件。如果不再需要，就把它拿出来。
- `security_executable`、`security_script`、`security_java`、`security_lua`：模组可能做的超出模组范围的事，在**安全**标签页中（见下文）。
- `compatible_copy`、`shadowed_copy`、`updated_since_last_play`：关于使用的是模组的哪一份副本、有什么变化的说明。

关于同一个定义的行可以用**按文件**展开，查看每个模组的文件。在那里点击一个定义可以在合并器中打开它。

### 修复按钮

- **启用 X** 或**禁用 X**：启用或禁用一个模组。禁用前会先询问；模组仍保持安装。
- **把 X 移到 Y 之前**：修改加载顺序。在“由你决定”的行上（两个模组定义了同一样东西），它显示为**改用 Y 的版本**。
- **从列表中移除 X**：把一个条目从列表中拿掉。
- **在创意工坊搜索“X”**和**打开创意工坊页面**：在你的浏览器中打开 Steam 创意工坊。
- **制作兼容副本**：在 `Zomboid/mods` 中为你的游戏版本制作一个创意工坊模组的改编副本。结果会显示改了什么，以及还有什么可能出问题。请从 Studio 启动游戏，让它使用这个副本。**回到原版**会移除副本。
- **保留你现有的版本**：在创意工坊更新到来之前，把模组今天的样子保存下来。你可以从模组列表中把它放回去（右键，保留的版本）。
- **自动合并**和**在合并器中打开**：在你最后加载的补丁包中解决文件或定义冲突。
- **从补丁包中拿出**：询问后把一个文件从你的补丁包中拿出；游戏下次启动时会重新读取模组自己的文件。
- **开启兼容层的 X 补丁**：开启某个已知问题所需的 Build 42 兼容层补丁。

每次更改都会有一行绿色文字确认，并显示**已保存到你的模组列表。**

### 一次修复多个

- **自动修复 N 个问题**会启用缺少的前置模组，并在需要时把模组往前移。它从不禁用任何东西，并跳过“由你决定”的行。它会先询问，而且模组列表可以撤销它。
- **自动合并 N 个文件**会把所有没有重叠修改的冲突文件合并到你的补丁包中。两个模组都改了同样行的文件会列出来，由你在合并器中决定。

### Studio 的规则和索引

Studio 内置了加载顺序规则、不能搭配的模组组合，以及附带修复办法的已知问题索引。它们随本应用的每个版本提供；不会下载任何东西，也不会发送任何东西。它们显示为 `community_*` 行。当模组自己的文件显示问题已经没有了（某次更新修好了相关文件），或者模组在发现问题之后有了变化、而你的游戏记录中不再出现那行日志时，已知问题会被自动略去。**不再发生**可以手动略去一项。

### 这台电脑学到了什么

除了自带的索引之外，每个应用还会从它自己所在的电脑上学习。它会在后台读取游戏保存的游戏和服务器会话日志（`Zomboid/Logs`），记录哪些模组被启用、是哪个版本，以及游戏把哪些错误归咎于它们（和监控中心显示的相同）。这些保存在 `Zomboid/PZModStudio_Learned.json` 中，不会发送任何内容。

当一个模组在同一版本、已安装的游戏版本上，于 3 次或更多游戏中出现同样的错误时，它会在诊断中显示为**在这台电脑上学到的**（`learned_issue`），以次数作为证据：“在你 14 次游戏中出现了 8 次”。如果本应用的索引已经提到了这个问题，就只显示索引那一行。日志同时归咎于多个模组的 Java 补丁不会被学习，因为无法判断是谁的。模组更新后，次数从零开始；当它最近 5 次游戏都没再出现（已修复，或修复起了作用）时，就不再显示。**不再发生**可以手动去掉它。诊断首页会说明它从多少次游戏中学习过。


### 医生与大脑

诊断首页有**问问医生**，这是一个不用 AI 就能回答的聊天：它根据你问的字词理解问题，用这台电脑学到的东西和本应用的工具（与 MCP 服务器的相同）组织答案。每个回答都会说明它来自哪个工具。你可以问它知道什么、游戏为什么关闭了、某个错误开始时有什么变化、哪些模组出问题、加载是否变慢了、修复是否起了作用、上次游戏更新带来了什么，或者说出一个模组的名字来查看它的历史。

它能容忍错别字和各种说法（“崩了”“卡死了”“有什么变化”），能读懂日期（“从昨天起有什么变化？”“这周”“从 12/11 起”）、“哪个加载最久？”或“哪个模组错误最多？”，还会跟着对话走：说到某个模组之后，你可以说“从什么时候开始的？”“禁用它”“记下来”或“给我看看”。不确定时它会用按钮问“是这些中的哪一个？”；当它没听懂、你用按钮告诉它你的意思时，它会在这台电脑上记住这个说法。每个回答先给结论，然后给出一条附带证据的建议（例如，几乎所有崩溃都是因为同时开着游戏和服务器时电脑内存不足），细节折叠起来，并有按钮跳到模组列表或诊断中相关的部分。

此外：

- **是哪个模组导致的？**它会比较有和没有每个模组的游戏：“有 X 时 7 次中有 3 次出问题；没有它时，196 次中有 24 次”，并说明有多大把握（相当确定、很可能、可能是巧合）。几乎每次游戏都启用的模组无法比较，不会被点名。
- 在聊天中**对半排查**：它会禁用你一半的模组（其他模组需要的保持启用），让你玩一局测试，你回答“还会发生”或“不再发生”，直到只剩一个。你的列表会被保存，最后会恢复。
- **报告**：玩过之后打开聊天，它会告诉你上次游戏的情况（游玩时长、如何结束、新的错误、起了作用的修复）。“这周发生了什么？”会对一段时间做同样的事。
- **关于本应用的问题**（“怎么创建配置方案？”“兼容副本是什么？”）：它会用本指南中的那一段来回答，并附上一个跳到该界面的按钮。
- **分组、配置方案和创意工坊**：“VP Base”会说明那个分组的状况，“配置方案 Knox Lives”会说明它最近几次游戏是否顺利；“X 有新版本吗？”和“X 的评论怎么说？”会读取它的页面。
- **一次问多个问题**（“有什么变化，哪些模组出问题？”）、当你在几个模组中做选择时它学会的**昵称**、撤销它上一次更改的**“撤销那个”**，以及**记忆**：下次它会提醒你上次聊的是哪个模组，以及它现在怎么样了。

**配合游戏（Studio Link）：**

- 在游戏主菜单上，PZ Mod Studio 卡片（右上角）会显示医生首先会说的话：用这个列表的最近几次游戏是否出了问题、上一次是否崩溃、哪些错误在重复。本应用每次检查时都会写入它，所以即使本应用关闭了，卡片也会显示它最后知道的情况。
- Link 会记一本日记：你载入了哪个存档、是否回到了菜单（而不是直接关闭窗口）。所以每次游戏都会显示“存档 X · 回到了菜单”，在本应用关闭时玩的那些也是。
- 暂停菜单（Esc）中有**标记此刻**：发生奇怪的事时，点一下它。然后问医生“我标记的时候发生了什么？”，它会告诉你游戏日志在那一分钟写了什么（从一分半钟之前到半分钟之后）。

它也可以改动东西，但总要你点**执行**：创建、重命名或删除当前配置方案的分组，把模组放进或移出分组（“把 A、B 分到 Maps 组”“把 A 移出 Maps 组”“把 Maps 组改名为 World”“删除 Maps 组”），为你没有分组的已启用模组建议分组（名称相同或需要相同前置的那些），以及写入或删除 **Studio 备注**（“给 A 备注：内容”“删除 A 的 Studio 备注”“把你学到的记下来”）。Studio 备注与你的备注分开保存，以紫色显示，并有自己的删除按钮；你的备注它永远不会写入、修改或删除。

大脑能从游戏记录中看出：

- **有什么变化**：当某个错误重复出现时，它从什么时候开始，以及与最后一次没有出现它的游戏相比有什么不同（新增、移除或更新的模组、它在顺序中的位置、游戏版本）。它只说那时有什么变化，而不说这就是原因。这会显示在诊断的那一行和模组的历史中。
- **记住的修复**：你在诊断中应用的每个修复都会被记录，之后的游戏会说明该模组的错误是否停止了。
- **游玩之前**：当用几乎相同列表的最近几次游戏连菜单都没进去或内存不足时，你点击“开始游戏”时本应用会说明这一点，并列出与最后一次成功进入存档的那次有什么不同，然后问你是否仍要游玩。
- **模组的历史**：在模组列表中，右侧面板的**在这台电脑上**部分。
- **加载变慢**，以及一次让多个模组同时出问题的**游戏更新**。
- **真正的崩溃**：Java 崩溃时会在游戏文件夹中留下一份报告（`hs_err_pid…log`）；大脑会读取它并把它关联到对应的游戏（“它崩溃了：电脑内存不足”或“那个库中发生了致命的 Java 错误”）。用 X 或 Alt+F4 关闭游戏不会留下报告，所以那永远不会被算作崩溃。

### 安全

**安全**标签页列出模组可能做的超出模组范围的事，从它的文件中读取：它带有的程序文件或脚本、能运行程序或访问互联网的 Java，以及调用了游戏自己的脚本从不调用的东西的 Lua。这些都不是定论：很多模组做这些事都有正当理由。大多数行是“提示”；“警告”标出的是没有任何模组有正当理由使用的模式。创意工坊模组的行有**打开创意工坊页面**。

### 每个模组的耗时

在**模组** > **每个模组的耗时**中：游玩时哪些模组拖慢了游戏。**测量**会把一个小的 Studio 模组（PZ Mod Studio Profiler）放在你模组列表的最前面，以及你最后游玩的存档中；启动游戏（如果开着就重启）并像平常一样玩几分钟。游戏会给每个模组的每个事件处理函数计时，并按模组汇总：它占用实际时间的比例、每秒的毫秒数，以及它最长的单次调用（很长的一次就是你看到的卡顿）。展开一行可以看到开销最大的处理函数及其文件和行号。**停止测量**会把性能分析器从列表和存档中再拿出去；最后的数字会保留。

模组的窗口、进度条和定时动作也会计算在内（显示为 Class:render、Class:update）；每个函数只计算它自己的时间。性能分析器会给每个处理函数增加一点自身的开销，所以用完后请停止它。

## 游戏

本应用对游戏本身（模组之外）所了解的内容。五个标签页：**实时**、**内存**、**启动**、**帧**和**磁盘**。

### 实时

游戏现在的占用：顶部是电脑的剩余内存（顶栏中的仪表会跳到这个标签页）。下面每个打开的游戏一张卡片：内存与其 Java 上限、CPU、它在哪个画面（菜单、连接中、游戏中）、它日志的最后一行、有多少个错误，以及打开它的文件夹和日志的按钮。游戏关闭时，显示上次已知的情况：上次启动、内存上限、内存不足的游戏，以及 Windows 内存不足的时候。

### 内存

在**游戏** > **内存**中：游戏的 Java 可以使用多少内存（`ProjectZomboid64.json` 中的 `-Xmx`），占电脑内存的多少，并针对你已启用的模组给出建议，最近某次游戏内存不足时还会有警告。选择一个值（2 GB 到电脑内存的一半），在游戏关闭时点击**应用**；它会在下次启动时生效，修改前的文件会复制一份到 `PZModStudio_Backups`。

每个配置方案保存自己的值：启用某个配置方案时，游戏就会使用它的内存值。没有设置值的配置方案使用最后一次选择的值。如果某次游戏更新把它自己的值放了回去，Studio 会在下次启动游戏时恢复你的值。

当过去 14 天内 Windows 自身在游戏打开时内存不足，也会在这里列出，并说明有什么帮助（更大的页面文件、关闭其他大型程序）。那不是游戏的 Java 内存，所以调高上面的值解决不了。

### 启动

在**游戏** > **启动**中：游戏花了多长时间进入主菜单，按阶段列出（模组文件、脚本、Lua、模型等），数据来自每次启动留下的日志。每次启动都会与你平时模组数量差不多时的启动对比；显示为琥珀色的阶段比平时慢得多。选择以前的某次启动可以查看它。

### 帧与卡顿

在**游戏** > **帧**中：游玩时的帧时间（fps、超过 25、50 和 100 ms 的帧）、已加载的区块，以及按模组列出的、让一帧停留最久的处理函数及其文件和行号。统计它们的是与**模组** > **每个模组的耗时**相同的性能分析器，所以请先在那里点击**测量**并玩几分钟。**重新读取**会读取最新的数字。

### 磁盘

顶部是**释放空间**：**清除缓存**会删除 Studio 为了不重复读取或请求同样内容而保存的东西（每个模组的检查结果、Steam 返回的信息、地图图片、翻译）；它会自己重新生成，永远不会动模组、存档、配置方案或备注。做完多人游戏测试后，**玩家 2 的文件夹**会把第二个游戏的 `Zomboid2` 文件夹（带有服务器模组的副本）移到回收站；链接到那里的开发中模组不会被动到，下次测试会重新创建它。测试进行时不能这样做。

在**游戏** > **磁盘**中：每个已安装模组占用多少空间，按作为一个整体的单位统计（一个创意工坊项目及其所有模组、`Zomboid/mods` 中的一个文件夹）。测量需要几秒钟。

- **没有任何东西使用它**（琥珀色）：没有配置方案包含它（无论启用还是禁用）；没有存档在列表中提到它；没有保存的服务器加载过它；它不在游戏当前的列表中。
- **到处都已禁用**（浅蓝色）：某个配置方案包含它但已禁用，并且没有存档或服务器使用它。
- **残留**：你已不再订阅的项目的创意工坊文件夹；Steam 有时会留下它们。
- **你上传的**：`Zomboid/Workshop` 中你自己的模组。会显示，但从不建议删除。

勾选你想删除的。创意工坊项目通过**取消订阅 N 个项目**删除（Steam 必须在运行，由它自己删除文件）。本地文件夹或残留通过**把 N 个文件夹移到回收站**删除：可以从回收站恢复。每种都会先列出名称并询问。游戏打开时不会把任何东西移到回收站。

下方的**游戏和 Studio 文件夹**：游戏、创意工坊模组、本地模组、存档、存档备份、保留的模组版本、模组列表备份、缓存、没装完的下载和日志各占用多少空间，并有打开每个文件夹的按钮。那里不会删除任何东西。

## 服务器

在这台电脑上运行的服务器（你从“服务器”界面启动的，或多人游戏测试的服务器），显示同样的卡片：内存与其上限、CPU、是否已启动、它日志的最后一行，以及有多少个错误。多人游戏测试期间也会显示它的玩家。没有服务器在运行时，会有一个按钮带你去**服务器**界面启动一个。

你加入的其他电脑上的服务器无法在这里测量：只能测量在这台电脑上运行的服务器。

## 小提示

- **模组**中的修复会保存到当前配置方案的模组列表中。
- 合并的文件和兼容层补丁会在下次启动游戏时生效。
- “刷满控制台”是根据上次游戏的 `console.txt` 测量的，所以要在你玩过之后才会更新。
- 在模组列表中点击问题小标签，会在这个界面打开对应的那一行。

# 模组合并器

模组合并器用来修复你的两个或更多已启用模组都修改了的文件，也可以让你修补某个模组自己文件里的错误。你的决定会放进一个补丁包：一个最后加载的小模组，这样游戏读取的就是你版本的这些文件。

## 补丁包是什么

- 补丁包是 `Zomboid/mods` 中一个名称以 `Z_PZModStudio_` 开头的模组文件夹（默认的是 `Z_PZModStudio_MergedPatch`）。
- 发布时，Studio 会把你合并好的文件写进去（Build 41 写在根目录，Build 42 写在它的 `42` 文件夹中），加上一个小的兼容文件，并把补丁包放在游戏模组列表的**最后**。游戏使用的是最后加载的那个模组的文件副本，所以你合并的副本会胜出。
- 补丁包有两种状态。**🟢 已打包 / 已关闭**表示它已发布，游戏会读取它。**🟡 已打开（草稿）**表示你正在编辑它；作为草稿时它会被移出游戏的模组列表，所以在你再次发布之前游戏不会读取它。
- 每个补丁包属于把它列在自己模组中的配置方案。在某个配置方案处于当前状态时创建的补丁包会被加入该配置方案。
- 补丁包会记住最后一次发布时的当前配置方案（卡片上的**制作于**，当现在是另一个配置方案时显示为琥珀色）：它的合并是为那个配置方案的列表而做的。如果某个配置方案没有自己的补丁包，顶栏中的**为“名称”制作补丁包**会以它的名字创建一个。

## 你会看到什么

没有打开补丁包时，你会看到**合并补丁包**列表。每张卡片显示补丁包的名称、它的文件、状态、所属的配置方案和这些按钮：

- **🔍 打开 / 进入补丁包**会在工作区中打开它，并扫描你已启用的模组中的冲突。
- **在模组列表中可见** / **在模组列表中隐藏**会在游戏的模组列表（`default.txt`）中启用或禁用该补丁包。
- 铅笔用来编辑它的名称和描述；垃圾桶会把它从磁盘上删除（会先询问）。重命名后，包含它的配置方案会使用新名称。
- 下载图标把它保存为可分享的 `.pzmerge` 文件；文件夹图标会在 Windows 资源管理器中打开它的文件夹。
- **其他配置方案的补丁包**显示属于其他配置方案的补丁包；**仅“名称”的**回到当前配置方案的补丁包。

顶栏中有**载入补丁包（.pzmerge）**，用来导入别人发给你的补丁包；还有**新建补丁包**，用来创建一个（名称、可选的描述，然后**创建补丁包**）。当前配置方案没有合并补丁包时，界面会这样提示，并说明什么时候需要一个，还有一个查看其他配置方案补丁包的按钮。Studio 自己的模组（Live IPC Bridge 和 Studio Link）不是合并补丁包：它们在下方，收在 **Studio 模组**下，你可以查看它们的文件，但不能编辑、重命名或删除。

## 在补丁包里工作

顶栏显示 **← 返回列表**、用来跳到另一个补丁包的**补丁包：**选择器、状态和可见性，以及这些按钮：

- **修补模组文件**：打开某个模组自己的文件来修复它（见下文）。
- **⚡ 全部合并并发布**：用自动引擎合并所有冲突的文件，并立即发布补丁包：它会被写入 `Zomboid/mods` 并放在你模组列表的最后，游戏下次启动时会读取它。之后请检查这些文件。
- **↩️ 全部取消合并**：丢弃这个补丁包中所有已保存的合并。会在 `Zomboid/PZModStudio_Backups` 中保留一份副本，已经发布的文件在你再次发布前仍然保留。
- **全部** / **不含重复**：隐藏各模组带有完全相同副本的文件，只列出真正的冲突。
- 文件夹、导出和重新扫描图标。
- **📦 打包并发布**：最后一步。它把每个文件当前的决定写进补丁包，并把补丁包放在游戏模组列表的最后。

左侧的 **VFS 冲突**列出每个冲突的文件，带有它的种类（Lua；**DEFINITION** 表示物品和配方脚本；**WORDS** 表示翻译）和状态：**需要检查**、**已自动合并**或**已解决**。

## 决定游戏读取某个文件的哪个版本

1. 在列表中点击一个文件。上半部分显示原版文件、每个模组的副本，以及每个模组相对于原版游戏改了什么的摘要；真正的冲突（同样的行被改得不一样）会被标出。点击一处更改，所有面板都会滚动到那里。
2. 在**游戏应该读取什么？**下选择一个答案：
   - **两个都保留**（用于 Lua 和其他文件）：所有模组的更改放在一起。两个模组改了同样的行时，最后加载的那个胜出，另一个保留在注释里。
   - **合并它们**（用于定义和翻译）：能同时容纳两个值的地方两个都保留；只能放一个的地方，保留游戏现在的做法，另一个留在注释里。
   - **只用（模组名称）**：该模组的版本。对于定义，其他模组中这个模组没有涉及的设置仍然有效。
   - **原版**：游戏自己的文件，就像没有任何模组动过它一样（原版游戏没有这个文件时不提供此项）。
3. 或者在下方的编辑器中编辑代码；之后它会显示**你自己的编辑**。模组面板上的**追加**和**移除**会加入或拿掉该模组的整份副本，**载入原版**会把原版文件放进编辑器。
4. 点击 **✓ 保存此文件的合并**。该文件变为**已解决**。
5. 所有文件都处理完后，点击 **📦 打包并发布**。

**恢复自动合并**会把自动合并的结果放回编辑器，**取消此文件的合并**会忘掉该文件已保存的决定。拖动面板之间的分隔条可以调整它们的大小。

## 修补某个模组的错误

当某个模组有错误、又没有什么需要合并时，使用**修补模组文件**。选择模组，再选择 Lua 或脚本文件，编辑后点击 **✓ 保存此文件的合并**。你的副本会放进补丁包，游戏会读取它而不是模组的，仅限这一个文件；该模组仍然启用，其余部分不受影响。保存一个没有任何改动的副本会被拒绝，因为那只会把文件冻结在今天的版本。

监控中心和诊断可以把你直接送到这里：会打开合适的补丁包，并在编辑器中打开错误中提到的文件，有时修复已经应用好了。

## 已打包的补丁包与就地发布

已打包的补丁包是只读的：它的文件隐藏在摘要后面，直到你点击 **🔓 取消合并 / 打开编辑**（或**解包以编辑**）并确认。解包会把已发布的文件从游戏中拿掉，直到你再次发布。

为了修补而打开的模组自己的文件是个例外：在已打包的补丁包中，保存它会**就地发布**。补丁包中的所有内容会和你的文件一起重新发布，补丁包保持已打包状态，游戏下次启动时会读取新文件。当诊断或监控中心把你送到已打包补丁包中的某个文件时，会直接显示该文件，无需解包。

## 分享补丁包

**载入补丁包（.pzmerge）**会导入一个补丁包文件。如果它是用你没有的模组、不同副本的模组或在另一个游戏版本上制作的，会弹出一个**发布之前**窗口列出它们，并为缺少的创意工坊模组提供**全部订阅**。最稳妥的做法是你们双方都使用最新的副本，然后在发布前重新扫描并再合并一次。

## 小提示

- 游戏在启动时读取补丁包：发布后，如果游戏正在运行，请重新启动游戏。
- 如果找不到游戏文件夹，界面会请你先在**应用设置**中设置路径。
- 当你离开一个有未保存编辑的文件时，会问你是否放弃这些编辑。
- 你删除的补丁包会从磁盘上移除；它合并过的模组不受影响。

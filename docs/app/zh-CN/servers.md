# 服务器

“服务器”界面顶部有三个标签页：**公共服务器**和**我的服务器**，用来找到并加入多人服务器；**建立服务器**，用来在这台电脑上运行你自己的专用服务器。在**建立服务器**下，有一条横栏显示你的服务器是否在运行，带有**查看运行情况**（打开“诊断 > 服务器”：内存、CPU、是否已启动以及它的日志写了什么）、**分享邀请**和重新读取服务器文件的按钮。

## 加入服务器：找到一个

在**公共服务器**下，点击**查找服务器**。Studio 会像游戏自带的浏览器一样，通过这台电脑上运行的 Steam 客户端向 Steam 请求所有 Project Zomboid 服务器（不需要密钥；查询期间 Steam 会显示你在玩 Project Zomboid）。服务器回应后就会出现；全部回应大约需要一分半钟。**停止**结束搜索，**重新搜索**从头开始。

用搜索框（**名称或地图**）和筛选缩小列表：**仅我的版本**、**有玩家**、**未满**、**无密码**、**有模组和原版** / **有模组** / **原版**，并按**玩家最多**、**延迟最低**或**名称**排序。右键点击服务器打开菜单：**查看它的介绍**、**加入**、**加星标**、**复制地址**、用它的模组创建配置方案，以及（对**我的服务器**中的服务器）**忘记此服务器**。

**我的服务器**保存你加了星标的服务器（**已加星标**）和你从这里加入过的服务器（**从这里加入过**）。要添加私人或朋友的服务器，在**按地址添加服务器**下输入它的地址（`ip:port`；不写端口则为 16261）、可选的名称和密码，然后点击**添加**。密码保存在 Windows 凭据存储中，绝不会写入文件。

## 加入服务器：加入

1. 点击一个服务器。右侧面板显示它的游戏版本、它是开放的还是仅限白名单、上次清档时间以及它的模组。每个模组都有颜色标记：**已安装并已启用**、**已安装**或**游戏会下载它**。
2. 如果服务器运行的版本与你的不同，会有警告提示：在两者一致之前（Steam 测试版分支），游戏不会让你进入。
3. 如果服务器有密码，输入服务器密码，并勾选**记住服务器密码**来保存它。已保存的密码会显示为一行绿字（**服务器密码已保存在 Windows 中**），而不是输入框：加入时 Studio 会自动填入。**更改**会打开输入框以输入新密码，**忘记**会删除它。你的账号密码在游戏的连接窗口中输入。
4. 如果游戏开着，先关闭它，然后点击**加入**。

游戏会在这个服务器的连接窗口启动，服务器密码已经填好；如果你在**你在此服务器上的用户名**中输入过用户名，用户名也会填好（Studio 会保存它；由 Studio Link 模组填入）。在那里输入你的账号密码并点击**连接**，没有用户名时该按钮不可用。新的用户名会在该服务器上创建一个新账号。游戏会下载服务器的模组并只在那里使用它们：你自己的模组列表保持不变；你加入时使用的配置方案会得到这些模组（见下文）。

有 Studio Link 模组时，该服务器还会加入游戏的**收藏**（游戏多人游戏界面中的收藏标签页），下面带有你的用户名，就像你用**添加服务器**和**添加新账号**添加的一样。这样如果你断线了，不用关闭游戏就能再次加入。它永远不会被添加两次，你的账号密码不会被保存；服务器密码会像游戏自己那样保存。

## 为服务器创建配置方案

服务器只公布它的前几个模组（Steam 会截断列表）。你从这里加入过一次之后，Studio 就知道完整的列表了，按钮会变成**用这 N 个模组创建配置方案**。在那之前，**用它公布的 N 个模组创建配置方案**使用的是不完整的列表。配置方案命名为“服务器：（名称）”，并保持服务器的顺序。创建配置方案之前，会指出现在没有安装的模组。

要用它来玩，加入之前在“配置方案”中激活它。每次你从这里加入，游戏载入服务器的模组后，这些模组会进入你加入时的当前配置方案：已启用，按服务器的顺序，包括游戏让你下载的那些。它的其他模组仍留在其中但被禁用，只在你这一端运行的除外（ZombieBuddy 及其仅客户端的 Java 模组，例如 Viewpoint）：它们保持你原来的设置。服务器面板会写明是哪个配置方案。

## 建立服务器：服务器列表

左侧的**服务器配置（.ini）**列出 `Zomboid/Server` 中的服务器配置，带有它们的模组数和创意工坊项目数，正在运行的那个显示**运行中**。输入名称并点击**创建**来新建一个，没有任何配置时可以点击 **⚡ 创建默认配置（servertest.ini）**。垃圾桶会从磁盘上删除一个配置（会先询问）。选择一个来查看它的标签页。顶部横幅显示**在线**或**离线**、**分享邀请**（复制一段邀请文字，包含名称、端口、最大玩家数、密码和模组数量；你需要自己填入公网 IP 并转发端口）以及一个重新加载服务器文件的按钮。

## 主机与启动

- **内存（-Xmx）**：给服务器 4、8、12 或 16 GB。
- **管理员密码**：服务器启动时设置 `admin` 账号的密码。Studio 把它保存在 Windows 凭据管理器中（绝不写入文件），所以连接到 Studio 的助手可以在不知道密码的情况下再次启动这个服务器。
- **认证与网络**：**启用 Steam** 或 **NoSteam（局域网）**。
- **启动专用服务器（名称）**会在它自己的控制台窗口中启动它。运行期间，**停止专用服务器**会停止 Studio 启动的服务器（绝不会动其他 Java 程序），**重启**会立即停止并重新启动它（要先提醒玩家，请使用**重启**标签页）。

**服务器程序。**除非你另行选择，服务器都从游戏自己的文件运行。**服务器程序**框提供官方的 **Project Zomboid Dedicated Server** 作为替代：Steam 免费提供的一个独立程序（app 380870），它可以和你的游戏处于不同的分支，并且单独更新。

1. 选择一个**专用服务器文件夹**：一个空的或新的文件夹，所在磁盘要有足够空间（不能是游戏文件夹，也不能是 `Zomboid`）。如果这台电脑上已经有专用服务器（来自 Steam 的“库 > 工具”，或以前的 SteamCMD），会被找到并提供。
2. 选择**分支**：**稳定版（public）**或**不稳定版（beta）**。它必须与加入者的游戏一致；框中会说明你的游戏在哪个分支，并默认选它。Steam 用密码保护的分支无法安装：框中会说明。
3. 点击**安装**。Studio 使用 SteamCMD，即 Valve 的命令行版 Steam。如果这台电脑上没有，它会先询问，然后从 Valve 自己的地址下载（约 3 MB），检查它是否由 Valve 签名，并让它自我更新。之后 SteamCMD 会从 Steam 下载服务器（几 GB）：框中显示每一步的百分比和 GB 数（42.22 约 7 GB），结束后显示文件夹大小。**停止**会结束它；再次点击“安装”会从中断处继续。
4. 安装完成后，选择**专用服务器**。从此服务器都从那个文件夹启动，使用同一个 Zomboid 文件夹（你的服务器配置、存档和 `Zomboid/mods`）。**游戏的文件**会回到通常的方式。请在服务器停止时更改。

**更新**会对那个文件夹和分支再次运行 SteamCMD（如果你改了分支则切换分支）。对于完整的安装，它只获取有变化的部分，几秒钟就能完成（没有变化时显示“Already up to date”）；如果之前的安装被中断，或文件检查被停止，它会检查每个文件，需要很多分钟。框中还会说明服务器启动时的游戏版本，以及它是否与你的游戏一致：游戏只能加入与自己版本相同的服务器。

带 ZombieBuddy 的 Java 模组还需要那个文件夹中有 ZombieBuddy 的 `zbNative.dll` 和 `ZombieBuddy.jar`：从游戏文件夹中复制过去（**模组与同步**里的**把 ZombieBuddy 的文件复制到专用服务器**按钮会帮你完成）（游戏用它启动时，ZombieBuddy 会把它们放在那里）。在它们到位之前，服务器会在没有代理的情况下启动，**模组与同步**会说明这一点。

**Java 模组（ZombieBuddy）。**带 Java 代码的 Build 42 模组需要 ZombieBuddy，而 ZombieBuddy 需要在服务器的命令行中加入它的代理。当服务器的 `Mods=` 中有 ZombieBuddy（也写作 `\ZombieBuddy`）时，Studio 会用 `-agentlib:zbNative=policy=deny-new` 启动它，这个标签页上会有一条说明。*deny-new* 表示服务器只加载这台电脑已经在 ZombieBuddy 窗口中批准过的 jar（它们保存在你用户文件夹中的 `.zombie_buddy/mod_approvals.json`），其余的不经询问一律拒绝：服务器没有窗口，询问会让它永远卡住。**模组与同步**会说明哪些 jar 还没有被批准。

## 重启

PZ Mod Studio 可以替你重启服务器，并先在游戏中提醒玩家。重启会通过 RCON 发送提醒（`servermsg`），然后 `save`，再 `quit`（服务器退出时会保存世界；只有在 90 秒内没有退出时才会强制关闭），然后用和原来相同的方式再次启动（相同的内存、Steam 或 NoSteam、程序）。

- **定时重启**：在一天中的指定时间（这台电脑的时钟），和/或从服务器启动起**每** 2 到 24 小时。距服务器启动不到 30 分钟的时间点会被跳过。
- **提前提醒玩家**：60、30、15、10、5 和 1 分钟，按你勾选的（默认 30、15、5 和 1）。消息使用本应用的语言。
- **此服务器的创意工坊模组更新时重启**：Studio 每 15 分钟向 Steam（它的公共 Web API）询问服务器 `WorkshopItems=` 中每个项目的最后更新时间。如果有项目在服务器启动后更新了，会以同样的提醒进行一次重启，服务器启动时会下载更新。
- **自行停止时重新启动**（默认开启）：崩溃之后，如果它之前已经启动成功（启动过程中就失败的服务器会再次失败，所以不会重新启动）。10 分钟内最多 3 次；之后它会保持关闭，标签页会用红字说明。手动启动会让计数从零开始。你要求的停止（停止、重启、助手、Discord）或管理员在游戏中的 `quit` 永远不会被当成崩溃。

标签页顶部说明接下来会发生什么：下一次定时重启，或正在倒计时的那一次及其时间和原因。**立即重启（提醒玩家）**会按你选择的分钟数开始倒计时（**不提醒（立即）**会马上重启）；**取消**会停止倒计时并通知玩家。**最近的重启**列出发生了什么以及原因：定时、模组更新、手动要求、崩溃后、保持关闭：崩溃太多次、自行停止、在本应用关闭时停止。

**只在本应用打开时。**重启由 PZ Mod Studio 执行。你关闭本应用后服务器会继续运行，但这时没有任何东西会重启它、提醒任何人，或在崩溃后启动它。计划会被保存（`Zomboid/PZModStudio_ServerSchedule.json`），再次打开本应用时继续；在本应用关闭期间停止的服务器会被记录，但不会被重新启动。

## 模组与同步

这里比较你已启用的模组和服务器 `.ini` 中的内容。服务器不会读取你的模组列表：它需要 `.ini` 中的三行：`Mods=`、`WorkshopItems=` 和 `Map=`，这三行必须一致，否则服务器会悄悄地在没有这些模组的情况下运行。Studio 会检查它们并列出问题（从未下载的模组、从未加载的项目、被忽略的地图）。

**把我的列表写入此服务器（Mods、WorkshopItems 和 Map）**会根据你已启用的模组按加载顺序写入这三行，其他设置保持不变。之前的文件保存在 `Zomboid/PZModStudio_Backups` 中。

已启用的 PZ Mod Studio 补丁包（`Z_PZModStudio_*`）也会写进 `Mods=`，但它是本地模组，不是创意工坊项目：这台电脑上的服务器有它，玩家无法通过下载得到它，而游戏在没有它时不让他们加入。请把补丁包分享给他们，或在写入列表之前禁用它。

同一次检查还会读取服务器会如何处理 **Java 模组**：ZombieBuddy 在这台电脑上还没有批准的 jar（新的，或之后有变化的：模组更新或重新构建就是一个新的 jar）会被服务器拒绝。启用该模组启动一次游戏，在 ZombieBuddy 的窗口中允许它，然后再启动服务器。你让 ZombieBuddy 拒绝的 jar，以及列表中没有 ZombieBuddy 时的 Java 模组（只会加载它们的 Lua），也会被指出。

在**主机与启动**中选择 **NoSteam（局域网）**时，它还会列出只在 Steam 创意工坊文件夹中的模组。不用 Steam 启动的服务器只读取 `Zomboid/mods`：它会报告这些模组“未找到”，并丢掉所有需要它们的模组。**把 N 个创意工坊模组复制到 Zomboid/mods** 会把每个模组的创意工坊文件夹复制到那里。是复制，不是链接：当一些创意工坊模组以链接（目录联接）方式放进 `Zomboid/mods` 时，NoSteam 服务器会在创建世界时崩溃，所以指向创意工坊文件夹的链接也会被标出，同一个按钮会把它替换为副本。在你自己的游戏中，副本也会优先于创意工坊项目。当 Studio 复制之后创意工坊项目又更新了，副本会被标为过时，按钮会再次复制。不是 Studio 放在那里的同名文件夹（你自己的副本）永远不会被替换。

**这个列表能在多人游戏中使用吗？**（**检查**）会给出列表的总体结论和每个模组的结论。它会读取每个模组的简介对多人游戏的说明，并列出模组的客户端代码直接进行、而游戏会通过服务器转发的调用；在多人游戏中，这些调用只会改变那一个玩家的世界，或者被拒绝。

## 玩家

**已连接的玩家**列出在线的人，从服务器自己的日志中读取，附带角色、Steam ID、进入位置以及是否死亡（游戏日志里没有延迟和生命值）。服务器运行期间，Studio 通过 RCON 与它通信（它 `.ini` 中的 `RCONPassword` 和 `RCONPort`；Studio 启动的没有密码的服务器会被设置一个密码）：

- 玩家行上的**踢出**会断开他们的连接；他们可以再次加入。你可以给出理由，他们会看到。
- **封禁**会禁止他们进入这个服务器，可以附带理由。要解除封禁，请使用服务器控制台：`unbanuser "name"`。
- 顶部的输入框会向游戏中的所有人发送消息（**发送给所有人**，或按 Enter）；它会显示在他们的屏幕上。

服务器的回应显示在输入框下方。

## 快速 .ini

编辑主要设置并点击**保存设置到 .ini**：**公开服务器名称**、**服务器密码（加入）**（留空即为开放服务器）、**管理员密码（-adminpassword）**、**最大玩家数**、**默认端口**、**公开描述**、**PVP 战斗**和**无人时暂停**。

## 所有选项

每个服务器选项和沙盒选项，按游戏显示的方式排列：按页面分组，附带说明、默认值以及你的模组的沙盒选项。**服务器**和**沙盒**切换列表，搜索可以按名称或说明查找选项，**只看不是默认值的**显示你改过的内容。选项的箭头会把它恢复为默认值。**保存**只写入你改过的内容，写入前会先备份两个文件（到 `PZModStudio_Backups/server_settings`），该服务器运行时会拒绝。Studio Link 会在你第一次打开游戏到主菜单时记录选项列表（游戏版本、语言或你的模组变化时会再次记录）。

## Discord

Discord webhook 让服务器可以向一个频道发消息：它启动、停止、崩溃或重启后恢复的时候，谁加入和离开，以及它的创意工坊模组何时更新、需要重启。不会 @ 任何人。

1. 在 Discord 中打开频道设置，依次进入“整合”“Webhooks”“新 Webhook”，复制它的 URL。
2. 把它粘贴到 **Webhook 地址**下并点击**保存**。它保存在 Windows 凭据管理器中，不会再显示出来。
3. 点击**发送测试**，然后查看频道。
4. 勾选**把此服务器的动态发到频道**，并选择事件：**启动、停止和崩溃**、**玩家加入和离开**、**重启**、**等待重启的创意工坊模组**。

**忘记它**会从这台电脑上删除该地址。每个服务器有自己的 webhook。

### 与游戏聊天：服务器自带的机器人

Project Zomboid 的专用服务器自带一个 Discord 机器人。Studio 在服务器的 `.ini` 中设置它；它运行在服务器内部，所以只要服务器在运行就能工作，即使 Studio 已关闭。

1. 在 Discord Developer Portal 中：**New Application**，然后 **Bot**：**Reset Token** 并复制它，再打开 **Message Content Intent**。
2. 在**与游戏聊天**中，粘贴**机器人令牌**，填写**聊天频道**（与 Discord 中的名称一致，不带 `#`），如果需要的话再填写**日志频道**，勾选**启用机器人**并点击**保存到 .ini**。
3. 点击**邀请机器人到你的 Discord**，选择你的 Discord 服务器，然后启动（或重启）游戏服务器。

之后游戏中的公共聊天会发到那个频道，在那里写的内容也会进入游戏。游戏从 `.ini` 读取令牌，所以令牌会写在那里：拥有该文件的人都能使用这个机器人。如果 `.ini` 中有命令频道，界面会警告你：任何人在那里写的内容都会作为管理员控制台命令执行；除非那个频道只有你能用，否则请**清除它**。

**自动更新的状态消息**（默认开启）会在频道中保留一条消息，显示服务器是否在运行、从什么时候开始，以及谁在线，而不是每次都发一条新消息。

### 从 Discord 发命令（Studio 打开时）

默认关闭，除非你开启。设置好上面的机器人后，填写**命令频道**和**可以使用命令的身份组**（与 Discord 中的名称一致），并勾选**启用命令**。Studio 每 5 秒读取一次那个频道并在那里回复；没有该身份组的成员会被告知不能使用。

- `!status` 和 `!players`：服务器是否在运行，以及谁在线。
- `!restart [minutes]`（1 到 60，不写则为 5）：与 **重启** 标签页相同的带提醒重启：玩家会在游戏中收到那里设置的提醒（时间内来得及的那些），频道也会收到通知，并记录在重启历史中；然后服务器保存、停止并重新启动。`!restart cancel` 会取消任何正在倒计时的重启，包括计划内的。
- `!save` 保存世界；`!msg <text>` 向游戏中的所有人说一句话。
- `!help` 列出这些命令。它们也有西班牙语版本（`!estado`、`!jugadores`、`!reiniciar`、`!guardar`、`!mensaje`）。

它们通过 RCON 与服务器通信：游戏创建的服务器没有 RCON 密码，所以 Studio 下次启动它时会给它一个随机密码（之前会先备份 `.ini`）；这也让**停止**可以在退出前保存。它们只在 PZ Mod Studio 打开时工作，并且永远不会执行手动输入的控制台命令。请使用只有管理员能看到的频道：聊天频道的内容也会进入游戏。

## 小提示

- 只有在 PZ Mod Studio 打开并托管服务器时，才会向 Discord 发消息。
- 启动服务器需要在**应用设置**中设置游戏文件夹。
- 加入服务器会启动游戏：请先关闭游戏。
- 要从这台电脑加入你自己的服务器，请使用它的局域网地址（例如 `192.168.0.10:16261`）：Steam 客户端无法加入 `127.0.0.1` 或这台电脑自己的公网 IP。用 **NoSteam（局域网）**启动的服务器需要用 `-nosteam` 启动的游戏（这时 `127.0.0.1` 可以用），而用 `-debug` 启动的游戏只能以管理员身份加入。
- 连接到 Studio 的助手（MCP）也能做同样的事：`server_start`、`server_status`、`server_stop`、`server_join`、`server_schedule`、`server_restart` 和 `dedicated_server`。

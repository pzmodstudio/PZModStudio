# Объединение модов

«Объединение модов» исправляет файлы, которые меняют сразу два или больше ваших активных мода, и позволяет залатать ошибку в собственном файле одного мода. Ваши решения попадают в пакет: небольшой отдельный мод, который загружается последним, так что игра читает вашу версию этих файлов.

## Что такое пакет

- Пакет — это папка мода в `Zomboid/mods`, имя которой начинается с `Z_PZModStudio_` (пакет по умолчанию — `Z_PZModStudio_MergedPatch`).
- Когда вы его публикуете, Studio записывает в него ваши объединённые файлы (для Build 41 и в его папку `42` для Build 42), добавляет небольшой файл совместимости и ставит пакет **последним** в списке модов игры. Мод, который загружается последним, — тот, чью копию файла использует игра, так что ваша объединённая копия побеждает.
- У пакета два состояния. **🟢 УПАКОВАН / ЗАКРЫТ** значит, что он опубликован и игра его читает. **🟡 ОТКРЫТ (черновик)** значит, что вы его редактируете; пока он черновик, он убран из списка модов игры, и игра не читает его, пока вы снова не опубликуете.
- Каждый пакет принадлежит профилям, в модах которых он есть. Пакет, созданный при активном профиле, добавляется в этот профиль.
- Пакет помнит профиль, который был активен при последней публикации (**собран с** на его карточке, янтарным цветом, если сейчас активен другой профиль): его объединения улаживают список именно этого профиля. Для профиля без собственного пакета кнопка **Пакет для «имя»** на верхней панели создаёт пакет, названный по нему.

## Что вы видите

Когда ни один пакет не открыт, вы видите список **Пакеты объединения**. Каждая карточка показывает имя пакета, его файлы, состояние, профили, которым он принадлежит, и такие кнопки:

- **🔍 Открыть / Войти в пакет** открывает его в рабочей области и ищет конфликты в ваших активных модах.
- **Виден в списке модов** / **Скрыт в списке модов** включает или выключает пакет в списке модов игры (`default.txt`).
- Карандаш меняет его имя и описание; корзина удаляет его с диска (сначала вас спросят). Профили, в которых он был, после переименования хранят новое имя.
- Значок загрузки сохраняет его как файл `.pzmerge`, чтобы поделиться; значок папки открывает его папку в Проводнике Windows.
- **Пакеты других профилей** показывает пакеты, принадлежащие другим профилям; **Только «имя»** возвращает к пакетам активного профиля.

На верхней панели есть **Загрузить пакет (.pzmerge)**, чтобы импортировать пакет, который вам прислали, и **Новый пакет**, чтобы создать его (имя, необязательное описание, затем **Создать пакет**). Если у активного профиля нет пакетов объединения, экран так и говорит и объясняет, когда пакет нужен, с кнопкой для просмотра пакетов других профилей. Собственные моды Studio (мост Live IPC Bridge и Studio Link) — не пакеты объединения: они лежат ниже, свёрнутые под **Моды Studio**; их файлы можно посмотреть, но не редактировать, переименовывать или удалять.

## Работа внутри пакета

Верхняя панель показывает **← Назад к списку**, переключатель **Пакет:** для перехода к другому пакету, состояние и видимость и такие кнопки:

- **Исправить файл мода**: открывает собственный файл одного мода, чтобы его исправить (см. ниже).
- **⚡ Объединить всё и опубликовать**: объединяет каждый конфликтующий файл автоматическим движком и сразу публикует пакет: он записывается в `Zomboid/mods` и ставится последним в вашем списке модов, а игра читает его при следующем запуске. Потом просмотрите файлы.
- **↩️ Отменить все объединения**: выбрасывает все сохранённые объединения в этом пакете. Копия сохраняется в `Zomboid/PZModStudio_Backups`, а уже опубликованные файлы остаются, пока вы снова не опубликуете.
- **Все** / **Без дубликатов**: скрывает файлы, где моды поставляют одинаковые копии, чтобы показывались только настоящие столкновения.
- Значки папки, экспорта и повторного сканирования.
- **📦 Упаковать и опубликовать**: последний шаг. Записывает текущее решение по каждому файлу в пакет и ставит пакет последним в списке модов игры.

Слева **Конфликты VFS** перечисляет каждый сталкивающийся файл с его видом (Lua, **ОПРЕДЕЛЕНИЕ** для скриптов предметов и рецептов, **СЛОВА** для переводов) и состоянием: **Нужна проверка**, **Объединено автоматически** или **Решено**.

## Решаем, что игра читает для одного файла

1. Щёлкните по файлу в списке. Верхняя половина показывает ванильный файл, копию каждого мода и сводку того, что каждый мод меняет по сравнению с базовой игрой; настоящие конфликты (одни и те же строки, изменённые по-разному) отмечены. Щёлкните по изменению, чтобы прокрутить к нему все панели.
2. В блоке **Что должна читать игра?** выберите один ответ:
   - **Оставить оба** (для Lua и других файлов): изменения всех модов вместе. Где два мода меняют одни и те же строки, побеждает тот, что загружается последним, а другой сохраняется в комментарии.
   - **Объединить** (для определений и переводов): что может вместить оба значения, хранит оба; где помещается только одно, остаётся то, что игра делает сегодня, а другое оставляется в комментарии.
   - **Только (название мода)**: версия этого мода. Для определения настройки других модов, которые этот не трогает, всё равно применяются.
   - **Ванильный**: собственный файл игры, как будто ни один мод его не трогал (не предлагается, если в базовой игре такого файла нет).
3. Или отредактируйте код в редакторе ниже; тогда будет показано **Ваша собственная правка**. **Добавить** и **Убрать** на панели мода добавляют или убирают всю копию этого мода, а **Загрузить базу** помещает в редактор ванильный файл.
4. Нажмите **✓ Сохранить объединение этого файла**. Файл становится **Решено**.
5. Когда все файлы готовы, нажмите **📦 Упаковать и опубликовать**.

**Вернуть автоматическое объединение** возвращает в редактор автоматическое объединение, а **Отменить объединение этого файла** забывает сохранённое решение для этого файла. Перетаскивайте полосу между панелями, чтобы менять их размер.

## Исправление ошибки в одном моде

Используйте **Исправить файл мода**, когда в одном моде есть ошибка, а объединять нечего. Выберите мод, затем файл Lua или скрипта, отредактируйте его и нажмите **✓ Сохранить объединение этого файла**. Ваша копия попадает в пакет, и игра читает её вместо копии мода, только для этого файла; мод остаётся включённым, а всё остальное в нём не тронуто. Сохранение копии без изменений не принимается, потому что оно лишь заморозило бы файл в сегодняшней версии.

«Монитор» и «Диагностика» могут отправить вас сюда напрямую: откроется нужный пакет, а файл, названный в ошибке, откроется в редакторе, иногда уже с применённым исправлением.

## Упакованные пакеты и публикация на месте

Упакованный пакет доступен только для чтения: его файлы скрыты за сводкой, пока вы не нажмёте **🔓 Разобрать / Открыть для правки** (или **Распаковать для правки**) и не подтвердите. Распаковка убирает опубликованные файлы из игры, пока вы снова не опубликуете.

Исключение — собственный файл мода, открытый для исправления: в упакованном пакете его сохранение **публикует на месте**. Всё, что есть в пакете, публикуется заново вместе с вашим файлом, пакет остаётся упакованным, а игра читает новый файл при следующем запуске. Когда «Диагностика» или «Монитор» отправляют вас к одному файлу упакованного пакета, этот файл показывается без распаковки.

## Обмен пакетами

**Загрузить пакет (.pzmerge)** импортирует файл пакета. Если он был сделан с модами, которых у вас нет, с другими их копиями или на другой сборке игры, окно **Перед публикацией** перечисляет их, с кнопкой **Подписаться на все** для недостающих модов из Мастерской. Самое надёжное решение — чтобы у вас обоих были самые новые копии; затем пересканируйте и объедините заново перед публикацией.

## Полезно знать

- Игра читает пакет при запуске: после публикации перезапустите игру, если она запущена.
- Если папка игры не найдена, экран попросит сначала указать пути в **Настройках приложения**.
- Когда вы уходите из файла с несохранёнными правками, вас спросят, оставить ли их.
- Удалённый пакет убирается с диска; моды, которые он объединял, не затрагиваются.

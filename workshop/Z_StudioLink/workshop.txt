description=[b]The Link makes the game's Mods screen and its Lua errors clearer, on its own:[/b]
description=[list]
description=[*][b]A clearer Mods screen[/b]: search, filters (problems, maps, can't load...), a mod comes on with what it requires and goes off with what needs it, a load order you can drag, undo. The game's screen is one button away.
description=[*][b]An error notice that names the mod[/b]: when Lua fails, which mod it was, which one called it, where. Copy report puts it on the clipboard for the mod's author, with the mod's id, version and Workshop item; every error of the session in one list, Copy all.
description=[*][b]Errors kept on disk[/b]: each error goes to Zomboid/Lua/PZModStudio_LinkErrorLog.txt as it happens, so a crash or a disconnect does not lose it.
description=[*][b]Shared files[/b]: when two mods you have on ship the same Lua file, only one copy runs. The Mods screen marks which mod overrides and which is overridden, and names the files.
description=[*][b]Reload mods[/b]: a Workshop item you subscribe to while the game runs shows up on the Mods screen without restarting.
description=[*][b]Server lines[/b]: the mods you have on, as a dedicated server's Mods=, WorkshopItems= and Map= lines in load order, ready to paste.
description=[*][b]For mod authors[/b]: one call, PZModStudioLink.registerReport("YourModId", fn), adds your mod's own debug information to the reports players copy for you. Other mods' debug reports, the ones they already register for error tools, are included too.
description=[/list]
description=
description=It is also the in-game side of [b]PZ Mod Studio[/b], a free, open-source program for Windows that manages your Build 42 mods: profiles, load order, error diagnosis, conflicts between mods, save backups and dedicated servers. With it, what the app knows shows up where you play: on the main menu, on the Mods screen and before a save loads. Both are free.

description=[h2]A check before every save loads[/h2]
description=Loading a save with different mods can lose items, vehicles or map areas for good. So when a save's mods changed since you last played it (added, taken out, updated, reordered), the Link shows what changed and you choose: [b]Load it[/b] (the app backs it up first), [b]Play on a copy[/b], or [b]Back[/b]. A save that uses mods outside the active profile does not load by mistake.

description=[b]The mod[/b]
description=[list]
description=[*]Only Lua: plain-text files you can read in the mod's folder. No Java, no DLLs, nothing compiled.
description=[*]It writes only what the game lets any mod write: its own small files in Zomboid/Lua, and your mod list, the same way the game's screen does.
description=[*]It runs no programs of its own and sends nothing anywhere. A Workshop page or the error log's folder opens only when you click for it, through the game's own functions; "Download" copies the address.
description=[/list]
description=[b]The app[/b]
description=[list]
description=[*]Open source under the MIT license: every line of the app and of this mod is on GitHub, to read or to build yourself.
description=[*]No account, no telemetry, no ads. It goes online only to browse the Workshop or Nexus, to translate a description when you ask, and to look for a new version once a day (it can be switched off).
description=[*]It never edits Workshop mods: fixes are separate mod folders you can delete. Your mod list is backed up every time it changes.
description=[*]A save is only changed when you say yes, and after a backup. The one game file it can touch is a Java-agent mod's launch line in ProjectZomboid64.json, backed up each time; Steam's "Verify integrity" restores it.
description=[*]Windows may show a SmartScreen notice the first time only because the program has no paid code-signing certificate.
description=[/list]
